# КазДемеу — ERP-система для швейного цеха (DRF + React)

Полный стек: **Django REST Framework** (backend) + **React / Vite** (frontend), JWT-авторизация, роли, журнал действий (аудит-лог), уведомления, Excel, QR, AI-ассистент (Anthropic API).

## Модули

| Модуль | Что делает |
|---|---|
| **Договоры** | Цепочка статусов (новый → согласование → в работе → закрыт/отменён, только разрешённые переходы), график платежей (оплата автоматически попадает в кассу), тех. спецификация, файлы (эскиз/макет/техкарта/фото или ссылка), история комментариев (кто/когда), «важный» комментарий подсвечивается и попадает в уведомления, экспорт/импорт Excel |
| **Аналитика** | Рейтинг ликвидности, себестоимость каждого изделия (материалы по BOM + труд + накладные), маржа %, структура расходов, помесячная динамика доходов/расходов/прибыли, статусы договоров (открыт/закрыт/просрочен), KPI-дашборд |
| **AI-ассистент** | Срез базы (договоры, изделия+BOM, склад, финансы) передаётся как контекст → вопрос-ответ на естественном языке; режим «тендер»: находит похожие заказы и готовит ценовое предложение от себестоимости |
| **Финансы** | Cash Flow (поступления/расходы/остаток), ДДС по месяцам, ОПиУ (по категориям, чистая прибыль, рентабельность), постоянные/переменные расходы, прогноз поступлений по воронке |
| **Склад** | Остатки материалов (по партиям и поставщикам), средневзвешенная цена, остатки готовой продукции, отгрузка клиенту, мин. остаток → автоматическое уведомление + авто-заявка поставщику, приёмка заявки → приход партии |
| **Швейный цех** | Производственный заказ: при запуске проверяется достаточность материалов и они списываются по BOM, при завершении (все этапы готовы) продукция приходуется на склад. Этапы: крой → пошив → отделка → ОТК → склад; на каждый этап — ответственный, нормо-часы vs факт (показывается отклонение) |
| **Дополнительно** | BOM-спецификация и проверка достаточности (`bom_check`), генерация QR-кода (SKU), прайс-листы по клиентам, ролевые права (admin/manager/accountant/warehouse/worker/viewer), аудит-лог (кто что изменил), система уведомлений (сроки, платежи, остатки) |

## Запуск

### Backend
```bash
cd backend
python3 -m venv venv && source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo        # демо-данные + admin/admin12345
export ANTHROPIC_API_KEY=sk-...   # для AI-ассистента
python manage.py runserver 8000
```

> **Важно:** без `python manage.py seed_demo` в базе нет пользователей — войти будет невозможно.

### Frontend
```bash
cd frontend
npm install
npm run dev        # http://localhost:5173  (/api проксируется на :8000)
```

Демо-логины: `admin / admin12345`, `aigerim / demo12345` (менеджер), `bolat / demo12345` (цех).

## Роли (право записи)
- **admin** — всё; **manager** — договоры, каталог, производство; **accountant** — финансы, договоры;
- **warehouse** — склад, производство; **worker** — этапы производства; **viewer** — только чтение.
Чтение открыто всем авторизованным пользователям.

## Основные API
```
POST /api/auth/token/                    JWT
GET  /api/analytics/dashboard/           KPI + помесячная динамика
GET  /api/analytics/products/            рейтинг ликвидности/маржи
GET  /api/reports/cashflow|pnl|forecast/ ДДС / ОПиУ / прогноз
POST /api/contracts/{id}/set_status/     цепочка статусов
GET  /api/contracts/export_excel/        POST /api/contracts/import_excel/
POST /api/production-orders/{id}/start|finish/
GET  /api/products/{id}/bom_check/?qty=N
POST /api/materials/check_stock/         проверка авто-заявок
POST /api/ai/chat/   POST /api/ai/tender/
GET  /api/audit-log/  /api/notifications/
```

## Заметки для продакшена
- `DATABASES` → PostgreSQL, `DJANGO_SECRET_KEY`/`DJANGO_DEBUG=0`, ограничить CORS конкретным доменом.
- Media-файлы перенести в S3/MinIO, gunicorn + nginx.
- AI: вызывается только на сервере, ключ никогда не попадает на клиент.
