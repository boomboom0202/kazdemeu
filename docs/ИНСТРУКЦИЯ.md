иначе система осталась бы без управления.

## 2. Как всё связано: жизненный цикл заказа

Главная идея системы — один сквозной поток данных:

```
ТЕНДЕР (план закупок) → выиграли → кнопка «В договор»
            ▼
Клиент → ДОГОВОР (статусы: новый → согласование → в работе → закрыт)
            │  график платежей ──→ оплата автоматически попадает в ФИНАНСЫ (Cash Flow)
            │  файлы (эскиз/макет/техкарта), комментарии (важные → в уведомления)
            ▼
     ПРОИЗВОДСТВЕННЫЙ ЗАКАЗ (ПЗ) на изделие из каталога
            │  Запуск: система проверяет достаточность материалов
            │          и списывает их со СКЛАДА по нормам BOM
            ▼
     ЭТАПЫ ЦЕХА (настраиваются технологом): крой → пошив → отделка → ОТК → склад
            │  на каждом этапе: ответственный, нормо-часы vs факт
            ▼
     Завершение ПЗ (все этапы готовы) → готовая продукция приходуется на СКЛАД
            ▼
     ОТГРУЗКА клиенту со склада → попадает в рейтинг продаж АНАЛИТИКИ
            ▼
     Оплата остатка по графику → договор можно ЗАКРЫТЬ
```

Параллельно работает контур снабжения:

```
Остаток материала < минимума → УВЕДОМЛЕНИЕ + авто-ЗАЯВКА поставщику
       → «Принять» заявку → приход партии на склад (с ценой и поставщиком)
```

## 3. Первичная настройка (порядок важен)

Перед реальной работой заполните справочники — именно в таком порядке. У каждого справочника
есть своя кнопка «+ …»; форма раскрывается прямо на странице.

1. **Сотрудники** — «Администрирование → Сотрудники / Роли», форма «Новый сотрудник».
   Создайте учётки, назначьте роли (см. таблицу прав выше).
2. **Постоянные расходы** — «Финансы → Постоянные расходы»: аренда, оклады АУП, коммуналка
   вводятся **один раз**. Без них накладные в себестоимости будут нулевыми. Там же выберите
   метод распределения и плановый фонд часов (или выпуск).
3. **Поставщики** — «Склад → вкладка Поставщики», кнопка **«+ Новый поставщик»**
   (название, телефон, email, БИН/ИИН).
4. **Материалы** — «Склад → вкладка Материалы», кнопка **«+ Новый материал»**. Задайте:
   - единицу измерения (м, шт, кг);
   - **минимальный остаток** — порог для авто-заявки;
   - основного поставщика — иначе авто-заявка не создастся.
   (Остаток пока 0 — он появится после прихода партий.)
5. **Приход первых партий** — «Склад → вкладка Партии / Приход»: материал, поставщик,
   количество и **цена за единицу**. Из цен партий считается средневзвешенная цена и
   себестоимость изделий. Только теперь у материала появляется остаток.
6. **Изделия** — «Производство → вкладка Изделия / BOM», кнопка **«+ Новое изделие»**
   (цена продажи, труд на 1 шт., норма времени в часах). Затем **кликните изделие в таблице** и в карточке
   справа добавьте состав материалов (**«+ В состав»**: материал + норма расхода на 1 шт.).
   После этого система сама считает себестоимость и маржу.
7. **Клиенты** — «Договоры», кнопка **«+ Новый клиент»** (сразу подставляется в форму договора).
8. **Категории расходов** — «Финансы», кнопка **«+ Категория расхода»**: название и тип
   (постоянные/переменные) — для структуры расходов в ОПиУ.

## 4. Модули

### 4.0 Тендеры / План закупок
Соответствует рабочей таблице «план закупок». Воронка:
**В плане → Заявка подана → Выиграли / Проиграли / Отклонена**, либо **Отбой** (не участвуем).

- Лот: площадка (госзакуп, Самрук-Казына, Eurasiantech), номер закупки и лота, от какого
  своего юрлица подаём, организация-заказчик, товар, количество, цена заказчика, срок подачи.
- **Экономика лота считается сразу**: наша плановая цена × количество − себестоимость = прибыль
  и маржа %. Если привязать лот к изделию каталога, кнопка **«Себест.»** подтянет расчёт по BOM.
- **Горящие сроки** подачи (≤3 дней) выводятся отдельным блоком сверху.
- **«В договор»** — выигранный лот одной кнопкой превращается в договор (клиент, сумма,
  название создаются сами), дальше работа идёт по обычному циклу.
- **Импорт/экспорт Excel** в формате вашей таблицы: колонки распознаются по названиям,
  если цена не указана, но есть сумма и количество — цена за единицу считается сама.

### 4.1 Договоры
- **Создание**: номер, заказчик, сумма, срок, тех. спецификация.
- **Статусы** меняются только по цепочке: новый → согласование → в работе → закрыт/отменён.
  Перепрыгнуть или вернуть назад нельзя — это защита от ошибок.
- **График платежей**: добавьте плановые платежи (аванс, окончательный расчёт).
  Когда деньги пришли — нажмите «Платёж поступил» и введите сумму.
  **Поступление автоматически запишется в кассу (модуль «Финансы»)** — не вносите его туда второй раз вручную!
- **Файлы**: эскиз, макет, техкарта, фото — загрузка файла или внешняя ссылка.
- **Комментарии**: история с автором и временем. Отметьте «Важный» — комментарий подсветится
  и попадёт в уведомления всем.
- **Excel**: «Экспорт» выгружает текущий список (с учётом фильтра), «Импорт» массово создаёт/обновляет
  договоры по колонкам number, customer, title, status, amount, signed_date, deadline, specification.
- Договор «В работе» с истёкшим сроком автоматически помечается **просрочен** и попадает
  в уведомления и аналитику.

### 4.2 Производство / Цех
- **Этапы цеха (конструктор)** — вкладка для технолога: маршрут собирается **с нуля**.
  Можно добавить свой этап (например «Вышивка логотипа»), задать порядок и норму часов,
  временно отключить галочкой или удалить. Новые производственные заказы создаются
  по активным этапам этого списка — жёстко зашитых 5 стадий больше нет.
- **Изделия / BOM**: клик по изделию — карточка с себестоимостью (материалы+труд+накладные),
  маржой и QR-кодом SKU. У изделия задаётся **норма времени** — по ней распределяются
  постоянные расходы (см. 4.4).
- **Производственный заказ (ПЗ)**: номер, изделие, количество, (опц.) договор.
  - **Запуск** — система проверит, хватает ли материалов (если нет — покажет чего и сколько
    не хватает), затем спишет их со склада по BOM.
  - У каждого этапа: назначьте **ответственного**, задайте **норму часов**; «Начать»/«Готово»
    фиксируют время — факт считается автоматически, отклонение от нормы подсвечивается.
  - **Завершить** можно только когда все этапы готовы; продукция приходуется на склад.

### 4.3 Склад
- **Материалы**: остатки, минимум, средняя цена, статус «мало/достаточно».
  Важно различать: **минимальный остаток** — фиксированный порог (задаётся вручную, сам не
  меняется), а **остаток** — живое число (приходы − расходы). Кнопка «История →» открывает
  движения по материалу.
- **Движения материалов**: полная история изменения остатка — приход партий (+) и списание
  в производство (−) с указанием причины и номера ПЗ. Отвечает на вопрос «куда делось со склада».
  Списание происходит при **запуске производственного заказа**, а не при закрытии договора —
  статус договора склад не трогает.
- **Партии / Приход**: приёмка закупленного материала (материал, поставщик, кол-во, цена, № партии).
- **Заявки на закуп**: ручные и автоматические. Кнопка «Проверить остатки» пробегает по всем
  материалам: где остаток ниже минимума — создаёт уведомление и авто-заявку основному поставщику.
  «Принять» заявку = оформить приход партии (спросит цену).
- **Готовая продукция**: движения (+ приход из производства, − отгрузка).
  **«Отгрузка клиенту»** — выберите изделие, количество и договор; остаток уменьшится,
  продажа попадёт в аналитику.

### 4.4 Финансы
- **Постоянные расходы — вводятся ОДИН РАЗ** (кнопка «Постоянные расходы»): аренда, оклады АУП,
  коммуналка. Действуют ежемесячно, пока не отключены галочкой. Система сама распределяет их
  в себестоимость каждого изделия — вручную «накладные» больше вбивать не нужно.
  - **Метод распределения** (там же): «на нормо-час» (точнее — учитывает трудоёмкость изделия)
    или «на единицу продукции» (проще). Укажите плановый фонд часов или плановый выпуск в месяц —
    система покажет ставку накладных (₸/час или ₸/шт).
  - **Переменные расходы** (материалы, сдельная оплата) вводятся каждый раз: материалы — через
    приход партий и BOM, оплата труда — в карточке изделия.
- **KPI**: остаток в кассе, доход/расход, чистая прибыль, рентабельность, ожидаемые поступления.
- **ДДС/Cash Flow** — помесячные поступления/расходы и накопленный остаток.
- **ОПиУ** — структура расходов по категориям, деление постоянные/переменные.
- **Прогноз по воронке**: неоплаченные остатки открытых договоров, взвешенные по вероятности
  стадии (новый 10% / согласование 40% / в работе 90%).
- **Новая операция** — ручной ввод денег. Для расходов укажите категорию.
  Поступления по договорам сюда вручную не вносите — они приходят из графика платежей.

### 4.5 Аналитика
- **Готовая продукция на складе — на какую сумму лежит**: количество, стоимость по
  себестоимости (сколько денег «заморожено»), по цене продажи и потенциальная прибыль,
  с разбивкой по изделиям.
- Рейтинг ликвидности — что продаётся лучше всего (по отгрузкам).
- По каждому изделию: продано / произведено / на складе, себестоимость с разбивкой,
  маржа и маржа %. «Чистая прибыль (оценка)» = маржа × продано — это оценка по нормативной
  себестоимости, фактическая прибыль смотрится в «Финансах».
- Сводка договоров: открытые / закрытые / просроченные / портфель.

### 4.6 AI-ассистент
- **Вопрос по базе**: спрашивайте на русском или казахском — ассистент видит срез базы
  (договоры, изделия с BOM, склад, финансы) и отвечает конкретными цифрами.
  Примеры: «По каким договорам скоро срок?», «Какая маржа у рабочего костюма?»
- **Тендер**: опишите лот («300 мед. халатов, бязь, с логотипом») — ассистент найдёт похожие
  заказы, посчитает себестоимость по BOM и предложит цену (мин/рекомендуемая/макс) с текстом
  предложения.
- Требуется ключ `ANTHROPIC_API_KEY` на сервере.

### 4.7 Уведомления (колокольчик сверху)
Создаются автоматически: срок договора близко/истёк, просрочен платёж, низкий остаток
материала, важный комментарий. Клик по ссылке ведёт к объекту.

### 4.8 Администрирование (только админ)
- **Сотрудники / Роли**: создание учёток, смена ролей на лету.
- **Журнал действий**: кто, когда, что создал/изменил/удалил — по всем ключевым объектам.

## 4.9 Исправление ошибок: редактирование и удаление
Почти у всех записей есть кнопки **«Изм.»** (редактировать) и **«Удл.»** (удалить):
- **Справочники** (поставщики, материалы, изделия, BOM, клиенты, категории расходов) —
  редактируются и удаляются на своих страницах.
- **Договоры** — удаляются из списка (вместе с платежами, файлами, комментариями);
  строки платежей/файлы/комментарии удаляются в карточке договора.
- **Финансовые операции** — удаляются из таблицы операций.
- **Производственные заказы** — удалить можно только **запланированный** (до запуска),
  чтобы не исказить остатки склада.

Если запись используется в других данных (материал в составе изделия, клиент с договором),
система не даст её удалить и покажет понятное сообщение — сначала уберите связанные записи.
