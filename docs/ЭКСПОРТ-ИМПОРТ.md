# Экспорт и импорт: какие файлы нужны

Форматов два — для договоров и для плана закупок (тендеров). Они устроены
по-разному, потому что решают разные задачи.

Общее для обоих:

- формат файла — **`.xlsx`** (Excel 2007 и новее). Старый `.xls`, `.csv`
  и Google Sheets напрямую не принимаются: сохраните через
  «Файл → Сохранить как → Книга Excel (.xlsx)».
- читается **только первый лист** книги;
- **первая строка — заголовки**, данные со второй;
- колонки распознаются **по названию, а не по порядку** — их можно менять
  местами, лишние колонки игнорируются;
- пустые строки пропускаются.

Самый надёжный способ получить правильный файл — **сначала выгрузить**
существующие данные, открыть выгрузку в Excel и править её. Тогда заголовки
заведомо совпадут.

## Договоры

Кнопки на странице «Договоры». Файл выгрузки — `contracts.xlsx`, лист «Договоры».

### Колонки

| Колонка | Обязательна | Что содержит |
|---|---|---|
| `number` | **да** | Номер договора. Это ключ: если такой номер уже есть — запись обновится, если нет — создастся |
| `customer` | нет | Название заказчика. Если такого нет в справочнике, он будет создан автоматически |
| `title` | нет | Краткое название, до 255 символов |
| `status` | нет | Код статуса, см. таблицу ниже. Неизвестное значение игнорируется, статус останется прежним. У существующего договора статус меняется только по цепочке — см. врезку ниже |
| `amount` | нет | Сумма договора. Пробелы, неразрывные пробелы, «₸» и запятую вместо точки система убирает сама: и `450000`, и `450 000 ₸` дадут одно и то же. Если в ячейке слово («договорная»), сумма будет нулевой |
| `signed_date` | нет | Дата подписания |
| `deadline` | нет | Срок исполнения |
| `specification` | нет | Тех. спецификация, обычный текст любой длины |
| `paid_amount` | — | Только в выгрузке. При импорте **игнорируется**: оплата считается по графику платежей |

Названия колонок пишутся латиницей и в нижнем регистре. Регистр и пробелы
по краям система приводит сама, так что `Number` и ` number ` тоже подойдут.

### Коды статусов

| Код | Что означает |
|---|---|
| `new` | Новый |
| `negotiation` | Согласование |
| `in_progress` | В работе |
| `closed` | Закрыт |
| `cancelled` | Отменён |

В файле должен стоять именно код (`in_progress`), а не русское название
(«В работе») — иначе строка импортируется, но статус не изменится.

> **Импорт не нарушает цепочку статусов.** У нового договора статус может быть
> любым: в систему вносят и те, что давно в работе. А у существующего действует
> то же правило, что и в его карточке — Новый → Согласование → В работе → Закрыт.
> Если в файле стоит запрещённый переход (скажем, `new` для договора «В работе»),
> строка загрузится, остальные её поля обновятся, статус останется прежним,
> а причина попадёт в список замечаний.

### Даты

Принимаются три вида:

- ячейка с **форматом даты** в Excel — предпочтительно;
- **текст `2026-09-15`** (год-месяц-день);
- **текст `15.09.2026`** (день.месяц.год).

Если Excel сам превратил ваш ввод в дату — всё в порядке, так и надо.
Непонятную дату система не примет, но потеряет только это поле: договор
загрузится, дата останется пустой, а строка попадёт в замечания.

### Пример минимального файла

| number | customer | title | amount | deadline |
|---|---|---|---|---|
| 2026-014 | ГКП Больница №2 | Халаты медицинские | 450000 | 2026-09-15 |

### Что вернёт система

После загрузки появится окно с итогом:

```
Импорт: создано 1, обновлено 0
```

Если что-то не сошлось, там же перечислены строки с номерами и причинами.
Замечание не отменяет загрузку строки: договор всё равно появится, просто
без того поля, которое не удалось разобрать. Строки без номера договора
пропускаются молча.

> **Импорт обновляет существующие договоры.** Совпадение идёт по номеру, и если
> в файле окажется номер уже существующего договора, его поля будут перезаписаны
> значениями из файла. Перед загрузкой большого файла имеет смысл выгрузить
> текущие данные — это готовый откат.

## План закупок (тендеры)

Кнопки на странице «Тендеры / План закупок». Файл выгрузки — `tenders.xlsx`,
лист «план закупок».

Здесь заголовки **на русском**, потому что формат повторяет рабочую таблицу
заказчика, чтобы её можно было загружать как есть.

### Колонки

| Колонка | Что содержит |
|---|---|
| Площадка | Название торговой площадки |
| Номер закупки | Номер закупки |
| Номер лота | Номер лота |
| От какой фирмы | Ваша компания-участник |
| Организация | Заказчик |
| Наименование товара | Предмет закупки |
| Дата окончания | Дата окончания приёма заявок |
| Время окончания | Время окончания |
| Срок поставки | Дней на поставку |
| Кол-во | Количество |
| Цена заказчика | Цена за единицу от заказчика |
| Сумма заказчика | Сумма по лоту |
| План цена | Ваша плановая цена |
| Себестоимость за ед. | Себестоимость единицы |
| Себес общий | Себестоимость по лоту |
| План сумма | Плановая сумма |
| Прибыль | Расчётная прибыль |
| Маржа % | Расчётная маржа |
| Статус | Статус лота |
| Решение | Решение по участию |
| Ответственный | Логин менеджера |

### Импорт терпимее, чем у договоров

Колонки ищутся **по вхождению слова** в заголовок, а не по точному совпадению.
Это сделано намеренно: в рабочих файлах заголовки приходят с опечатками
и лишними словами. Система понимает варианты:

- «Дата окончание» и «Дата окончания»
- «Время окончаня» (с опечаткой) и «Время окончания»
- «От какой фирмы» и «С какой фирмы»
- «Наименование товара» и «Предмет закупки»
- «Время поставки» и «Срок поставки»

Если заголовок первой колонки повреждён или пуст, она всё равно считается
площадкой — так устроено под конкретный рабочий файл.

### Как узнаётся лот при повторной загрузке

Ключ — **«Номер закупки» + «Номер лота»**. План присылают заново по нескольку
раз, и повторная загрузка того же файла не плодит дубли: совпавшие строки
обновляются, новые добавляются. Система отчитывается обоими числами:
`Импорт: добавлено 0, обновлено 3, пропущено 0`.

Строки **без номера закупки** узнать не по чему — такие каждый раз добавляются
как новые. Если план приходит без номеров, заполните их хотя бы условно
(«1», «2», «3»), иначе повторная загрузка задвоит эти строки.

Строки **без наименования товара** пропускаются молча — так отсекаются пустые
и служебные строки в конце файла. Их число видно в поле «пропущено».

### Откуда берётся статус

Порядок такой:

1. если в файле есть колонка **«Статус»** — берётся она (подходит и русское
   название «Заявка подана», и код `submitted`). Эта колонка есть в нашей же
   выгрузке, поэтому круговой рейс «выгрузил → поправил в Excel → загрузил»
   статус не сбрасывает;
2. если такой колонки нет (обычный рабочий файл заказчика) — статус собирается
   по отметкам: заполненная «Заявка подана» даёт «Заявка подана», «Заявка
   отклонена» — «Заявка отклонена», слово «отбой» в колонке решения —
   «Отбой (не участвуем)»;
3. если ничего из этого нет — «В плане (изучаем)».

### Что система досчитывает сама

- **Цена за единицу**, если её нет, но есть «Без НДС сумма» и «Кол-во»:
  делит одно на другое.
- **Прибыль, маржа, суммы по лоту** — всегда считаются, в файле их можно
  не заполнять.

Себестоимость система не выдумывает. Пока колонка «Себестоимость за ед.»
пуста, маржа в списке будет 100 % — это не ошибка, а следствие нулевой
себестоимости. Её либо вписывают в файл, либо подтягивают из каталога
кнопкой в карточке лота, связав лот с изделием.

## Частые ошибки

| Симптом | Причина |
|---|---|
| «Файл не передан» | Файл прикреплён не в то поле. Пользуйтесь кнопкой на странице, а не запросом вручную |
| Импорт прошёл, но записей ноль | Пустая колонка `number` (договоры) или «Наименование товара» (план закупок). Такие строки пропускаются |
| Дата не заполнилась | Написана словами или в непривычном виде. Нужен формат даты Excel либо текст `2026-09-15` / `15.09.2026` |
| Статус договора не поменялся | Либо в файле русское название вместо кода (`in_progress`, а не «В работе»), либо переход запрещён цепочкой — смотрите замечания в окне итога |
| Сумма получилась нулевой | В ячейке не число, а слово («договорная»). Пробелы, неразрывные пробелы, «₸» и запятую вместо точки система убирает сама |
| Ошибка при открытии файла | Файл сохранён как `.xls` или `.csv`. Пересохраните в `.xlsx` |
| Заказчик задвоился | В файле название написано иначе, чем в справочнике («ТОО Ромашка» и «ТОО "Ромашка"»). Совпадение идёт по точному названию |
| Лоты задвоились после повторной загрузки | В строках пустой «Номер закупки» — по нему узнаётся лот. Заполните номера |
| Маржа показывает 100 % | Себестоимость за единицу равна нулю. Впишите её в файл или подтяните из каталога |

## Права доступа

Выгружать может любой, у кого есть доступ к разделу на чтение. Загружать —
только те, у кого есть право записи в этом разделе:

| Раздел | Кто может загружать |
|---|---|
| Договоры | администратор, менеджер, бухгалтер |
| План закупок | администратор, менеджер, директор |

У кого права только на чтение, тот кнопки «Импорт из Excel» не увидит вовсе —
кнопка скрыта, а не отключена. «Экспорт в Excel» видят все, кому раздел открыт.

Точечные права работают и здесь: если человеку выдать `contracts.contracts`
на изменение, он сможет загружать договоры, даже если его роль этого не даёт.

**Выгрузка отдаёт всё, а не то, что на экране.** Поиск и фильтр по статусу
в списке на файл не влияют — в выгрузку попадают все записи, которые человеку
видны. Отбирать нужное удобнее уже в Excel.
